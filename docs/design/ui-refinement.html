Pick one

Three options, same theme

All three keep the current palette (neutral-100 canvas, white surfaces, stone ink, dark stone sidebar, lime #c1ff72, navy #002f43) and the current fonts (Montserrat, Inter, Shippori Mincho). They differ only in proportion, density, corner radius, elevation and which colour fills the main button. Switch with the picker at the top; every component and page below re-renders in that option.

Option A

Paper

Calm and editorial. Typography and whitespace carry the hierarchy, not boxes.

  • Hairline borders, no shadows, 12–16px radius
  • Lime is the one primary action per view; navy only for focus, links and data
  • Words as a quiet divided list; decks as light cards
  • Closest to Things / Linear in feel
Option B

Console

Dense and precise. Fits more decks and words on screen, so it suits power users.

  • 6–10px radius, 32px controls, monospace numbers
  • Navy fills the primary button; lime marks “due” and active state only
  • Decks and words as table rows with column headers
  • Closest to Vercel / Linear settings
Option C

Studio

Soft and expressive. Keeps today’s dark hero tiles but puts them on a strict grid.

  • 20–28px radius, soft shadow instead of borders, pill buttons
  • Dark “Today” tile with lime numbers; big display figures
  • Words as separate cards with large Mincho terms
  • Closest to the current voca-bak look, made consistent

Why it feels broken

What the current UI gets wrong

Found by reading every page in fe/src/features and the shared components. Every option below fixes all of these.

  1. 01Five corner radii side by side. Cards use 32px (rounded-card) next to 16px (rounded-2xl) cards on the same page, plus 12px inputs and 8px buttons. Fix: three radii, picked by nesting depth.
  2. 02Two filled colours compete for “main action”. “Study” is navy on deck cards and lime on the dashboard; “Add deck” is navy and “Create your first deck” is lime. Fix: one primary fill per option, used once per view.
  3. 03Every page builds its header differently. Greeting on the dashboard, icon tile + title on Decks/Discover/Settings, back link + five stacked lines on a deck, no header on study setup. Fix: one PageHeader (back link or eyebrow, title, meta row, actions).
  4. 04Maturity colours disagree. Dashboard: new = light lime, learning = blue, mature = lime. Deck page: stone, amber, navy. Fix: one scale: new stone-300, learning lime, mature navy.
  5. 05Cards without titles, states without design. The Activity card shows only ‹ › arrows; loading and errors are grey text lines that make the layout jump. Fix: every card has a title row; skeletons keep the layout; errors are an alert with Retry.
  6. 06Deck page is noisy. Four equal buttons in a row, and every word card repeats “Edit / Delete” as text. Fix: one primary action plus a ⋯ menu; word actions are icon buttons that show on hover.
  7. 07Search behaves two ways. Live filter on Decks and Discover, a submit button on the deck page. Fix: one Toolbar with live search everywhere.
  8. 08Selection looks different everywhere. Session size uses solid lime, drills use a lime tint, Settings uses yet another segment style. Fix: one segmented control and one choice card.
  9. 09Type scale has no steps. Page titles are 24 or 30px, numbers are 11px in the heatmap and 60px in the streak, and Montserrat is applied ad hoc. Fix: six fixed sizes and clear roles for each font.
Taste, written down

Principles behind every option

Taken from the references at the end of this page and applied to Voca’s screens.

Hierarchy from weight and colour firstMake secondary text quieter (stone-500) before making primary text bigger. Only page titles and key numbers get size.
Space shows groupingTight inside a group (6–8px label→control), loose between groups (24–48px). No divider where space already separates.
One primary action per viewOne filled button per screen region. Everything else is secondary, ghost or in a ⋯ menu.
Fixed scales onlySpacing 4·8·12·16·24·32·48; three radii; six type sizes. No one-off values.
Radius by nestingAn inner element’s radius is smaller than its container’s (container − padding), so corners look concentric.
The word is the heroTerms are always Shippori Mincho and the largest thing in their row. Chrome stays neutral so the script stands out.
Colour means somethingLime = due / primary / success; navy = mature / focus / link; red = wrong / destructive. Never decoration.
Every state is designedEach card has loading (skeleton), empty, error (with Retry) and loaded states with the same footprint.

        How the chosen option ships

        1 · Tokens + primitivesOption tokens go into styles/tokens.css and the Tailwind @theme. Then refine Button, Card, Input, Badge, and add Toolbar, SegmentedControl, ChoiceCard, Tabs, Menu, Alert, Skeleton, EmptyState, PageHeader.
        2 · Component testsThe fe has no component tests today. Each primitive gets a bun test with happy-dom + Testing Library: roles, aria-pressed/selected, disabled, keyboard (menu Esc, study keys 1–4).
        3 · Pages, one task eachShell + Dashboard · Decks · Deck page · Study · Discover · Settings + Auth + Landing. Disjoint files, so they can run in parallel through the agent loop.
        4 · Visual checkbun scripts/shots.ts at 1280 and 390 for every route, so you review screenshots instead of reading class names.
